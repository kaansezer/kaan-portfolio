# Project Context & Workflow

## Before Starting Work
1. **Read PROJECT_MAP.md** first for architecture, tech stack, routes, components, styling
2. **Read .claude/WORK_STATE.md** before continuing existing work to understand progress

## General Principles (Token Efficiency)

### Repository Navigation
- Use `git status` and `git diff` to understand recent changes
- Do NOT perform repository-wide scans unless absolutely necessary
- Only inspect files relevant to the active task
- Do not repeatedly re-read unchanged files unless necessary

### Making Changes
- Prefer targeted edits over broad refactors
- Preserve existing functionality unless explicitly changing it
- Batch related changes together in a single task
- Keep explanations concise

### Design & UX Work
- Do not repeatedly run expensive UX audits
- Use ux-ui-agent-skills only when the task explicitly requires design feedback
- Focus on specific problems, not comprehensive redesigns

### After Work
- Update WORK_STATE.md with completed work, files modified, and remaining tasks
- Update PROJECT_MAP.md only when architecture or structure changes
